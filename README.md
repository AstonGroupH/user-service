Правила работы.

1. Все наработки сливаются в develop (rebase с флагом squash). Заголовок коммита должен носить 
   суть сделанной работы. Имя фичи и краткое описание, что сделано.

2. Каждый участник делает от develop ветку, в которой ведет работу над задачей. 

   При реализации своей задачи в каждом модуле, надо делать ветку с префиком: feature_moduleN_name_task
   где moduleN - номер текущего модуля, в котором выполняется задача. name_task - краткое имя задачи.

3. Свой MR (merge request) можно залить только, если получено два approve.

4. Для кадого модуля будет добавляться файл Module_N.md, в котором будет помечен текущий лид, список
   участников. Описание задачи, которая закреплена за участником. Этот файл создает и заполняет текущий лид.
